# Native role policy

`index.mjs` is a Cordis service loaded into the same host as native Agent Teams and SessionController. Configure `stateDirectory`, `leadRole`, and a `roles` map. Each role has `description`, `instructions`, a registered LLM `provider`, `model`, and optional `reasoningEffort`. The native provisioning backend is separately fixed to in-process `spawn`. Role configuration never accepts credentials or endpoint overrides.

The bridge calls `prepareLead(sessionId, roleName?)` before native Session creation. This writes an immutable private Lead snapshot. The serial, awaited `agent/created` listener installs the initial route with `agent.model.select`, a Session role record, and scoped required context before queued work can run. Scoped context enters native durable prompt snapshots rather than an unlogged request mutation. Later explicit native Web model selections survive resume; the configured role snapshot remains unchanged. A recovered binding without a subsequent own-suffix native `model/selection` or `request/header` event initializes its route again, covering a crash between binding and selection. Fallback Agent options and selections that precede the binding never count as initialization evidence.

The Lead's `spawn_role_teammate` tool selects one allowlisted role. Names identify member instances, so several names may use the same role. The service flushes the complete immutable role reservation into the Lead log before calling native `agentTeams.spawnTeammate`. Native `team/member` records provide child identity; the child's awaited creation listener resolves the reservation and persists its own binding. A retry with changed content fails; changed role configuration applies only to new names. After interruption or restart, native messaging resumes the same member.

The native `tool-agent-team` plugin remains unchanged. It supplies the existing list, task/CAS, message, wait and interruption tools. Its original `spawn_teammate` remains visible, but a scoped native monotonic tool guard always refuses execution for bound members. The enhanced tool is the only permitted creation path. The shipped Team composition must also disable general subagent spawn/fork/control tools. Native public `tools.restrict` cannot hide a scope-local tool, and duplicate registrations in an exact Agent scope fail, so this supported guard avoids a native source fork. The guard is checked in the shared native execution pipeline before tool body dispatch, including programmatic tool execution. The guard belongs to the exact Agent lifetime and survives role-service unload, while the enhanced tool and role context are removed. This keeps creation closed during a service reload; pending enhanced calls observe service cancellation. A reload may add another equivalent monotonic guard, released with the Agent.

`bindings(rootSessionId)` explicitly inspects native role records and request headers. It separates configured routes, live `agent.model.current()` selections, and last-request evidence. Unloaded members report `selected: null` while their last request remains available. `lastRequest` reflects the durable native request header, not initial Agent options. Costs and provider billing are not inferred.

The first release accepts text prompts. It does not promise image, audio, file-attachment or video propagation across role routes. Native workspace, sandbox and approval behavior still owns tool access.
