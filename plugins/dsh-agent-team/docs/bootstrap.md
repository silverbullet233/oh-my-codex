# Bootstrap instructions for an AI Agent

Use this guide only when the user authorizes plugin initialization. Main may prepare the plugin and check health before a DSH Lead exists. This does not authorize project work, Team creation, inference, direct teammate instructions or provider credential handling.

The release target is **catalog v0.3.1 / plugin 0.4.3**, exact official **DSH / Team Profile 0.2.2-alpha.3** and built **dsh-team-roles 0.6.1**. Catalog publication is pending until the reviewed commit is tagged and its workflow/assets are verified. Verify the fixed Release before installation; older immutable tags keep their original behavior. Do not mix versions.

There is no auto-discovery of an independently installed runtime. Follow the complete [English installation guide](https://github.com/silverbullet233/oh-my-codex/blob/main/docs/dsh-agent-team-install.md). Its commands cover both an authorized existing Codex home and an isolated home, plus backups, conflicts and failure recovery.

1. Locate the intended Codex home, installed plugin and authorized workspace. Check Node >=24.9.0, npm, Git and `codex plugin` support. Do not upgrade global tools, copy authentication or print private configuration. Existing profile changes require authorization for that exact home.
2. Inspect inventory and reuse a complete matching healthy installation. Stop on version, workspace, ownership, symlink, partial-install or process-liveness uncertainty. Do not replace a registered marketplace or a live Host automatically.
3. For a fresh install, register the verified fixed catalog tag and install plugin 0.4.3. Capture the returned `installedPath`. Read this plugin's transport with `CODEX_HOME=/absolute/authorized-codex-home codex mcp list --json`, privately filtering by its exact installed entrypoint.
4. Discover the manifest-bound paths. The server's standard `env` expands `${PLUGIN_DATA}/runtime/node_modules/@deepseek-ai/dsh` and `${PLUGIN_DATA}/dsh-home`. Require absolute paths under the same authorized canonical plugin-data parent. Strip the exact `/node_modules/@deepseek-ai/dsh` suffix from the runtime path to get npm's `--prefix`. These are the installation targets; arbitrary terminal exports do not override them.
5. Install exact `@deepseek-ai/dsh@0.2.2-alpha.3` in that empty runtime directory with private npm config/cache, `--save-exact --ignore-scripts --no-audit --no-fund` and the official registry. Verify the package name/version. Download the built host 0.6.1 archive and `SHA256SUMS` from the fixed Release, and require both the manifest check and pinned SHA-256 `00f3fbf359289afa648fe8ef57b01739631c3ea70184f7f9351323dae1fcf669` in the complete guide. No source archive, branch, latest or fallback version is supported.
6. Supply the two discovered DSH paths to the setup process and run the installed `scripts/setup.mjs` with the verified archive and authorized workspace. Setup installs the exact Team Profile/Host into an empty private Home; complete matching installations are read-only reuses. It refuses interrupted/mismatched state and does not repair or migrate it.
7. Verify static MCP identity/protocol and all 18 exact tool names. Run CLI health if local native authorization state and loopback listeners are allowed. Then restart/reload Codex using the same home and supported Node on PATH, and call the **actual `dsh_team_health`**. Require API 1, compatible capabilities, exact runtime, expected roles and matching attributed Home/runtime/workspace. CLI-only health is insufficient proof of MCP connectivity. Report CLI and actual MCP results separately. The 0.4.3 manifest supplies paths on every launch; no DSH terminal exports are required for MCP. The old 0.4.0 forwarding failure is not a working installation route.
8. Initialization must not invoke `dsh_team_create`, `dsh_team_web` or `dsh_team_web_url`, open a browser, configure a provider or call a model. If cleanup is authorized, shut down only this attributed idle host with `dsh_team_shutdown` and check the result. Never force-stop unknown processes or delete/migrate personal state. Preserve uncertain outcomes for inspection.

Never add Git tokens, provider keys, launch tokens or API cookies to MCP configuration. DSH may create its own local browser/API grant during first startup; the installer does not provision provider credentials. The explicit `dsh_team_web_url` is a separate secret-bearing request requiring an existing managed Lead/root Team and explicit user intent.

## Permission default

Plugin 0.4.3 uses native full access by default: `danger-full-access`, approval `never`, network enabled intent. It does not automatically inherit Codex sandbox/approval/network settings or invoke a Codex launcher. This can allow writes outside the project wherever the process has access. Outer OS/process/admin restrictions remain effective; network intent is not a connectivity guarantee. Explicit profiles remain available and fail closed when invalid. See [Team permissions](permissions.md).
