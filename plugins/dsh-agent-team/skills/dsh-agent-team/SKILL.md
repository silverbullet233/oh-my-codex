Use the eight dsh-agent-team MCP tools. Call health first: it lazily starts/reuses a dedicated ordinary DSH Web host through official Connection/Typert Gateway. Require native business API 1 and the advertised capabilities. Never adopt or stop an unrelated user Web process. If setup/runtime is missing, report the exact prerequisite from the getting-started guide; do not modify global installations or personal profiles.

Role policy and credentials live in native DSH. Open its authorized page with dsh_team_web when requested or needed for native observation/approval. The tool returns a clean origin and performs the native browser handoff; never expose launch tokens or API cookies. Inspect the host catalog before choosing roles. Empty catalogs use native main Agent selection and teammate inheritance; omit leadRole. Explicit role names must come from the catalog, and later edits apply only to new reservations.

Create uses a durable caller key; reuse it only with identical content. Keep teamId and input IDs across uncertain outcomes. Native writes are never automatically replayed. Inspect status before explicitly retrying an uncertain request. A cold create retry may require explicit continuation using the returned input ID and continue=true. Send follow-ups to the same Team so native member identities and immutable snapshots survive. Text input only.

Acceptance does not imply processing or completion. Read whole-Team completion evidence: Lead completion and process exit are insufficient. Configured, selected and last-request model routes are distinct; unknown usage/fees and unloaded selections remain unknown.

MCP EOF closes only the client Peer; native work continues. Stop interrupts the whole Team without rolling back files or clearing inboxes; cancellation acceptance and observed quiescence are separate. Use dsh_team_shutdown only when ending the owned instance is requested or appropriate after work: it refuses active/unknown native work, fences admission and gracefully signals only its attributed host. A host retained during startup or uncertain shutdown must not be replaced with another writer.

Use native Web for tools, tasks, messages and approvals. Never approve on the user's behalf, invent provider endpoints or change Codex's normal model, subscription or entrypoint. DSH remains opt-in.
